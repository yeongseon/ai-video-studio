## Getting Started

### Access URLs

- **Studio Web UI**: `http://localhost:5174`
- **API**: `http://localhost:8000` (internal prefix: `/api/creator`)

### Starting Services

```bash
cd short-form-studio
docker compose up -d
```

Required services: `postgres`, `redis`, `api`, `worker`, `studio-web`

For frontend live-reload during development, run the frontend directly:

```bash
cd apps/studio-web
npm run dev
```

Optional services (GPU required):
- `stable-diffusion` — Image generation (6GB+ VRAM)
- `tts-qwen3` — TTS voice generation
- `stt-whisper` — Subtitle generation (Whisper small, configurable)

> ⚠️ On a GPU with limited VRAM (e.g. GTX 1660 SUPER 6GB), you cannot run all GPU services simultaneously. Start only the services you need.

## Creating a Project

Click the **"Create New Project"** button in the Studio Web UI. Two tabs are available:

> The current UI supports two starting modes: **Idea** and **JSON**.
> `URL` and `Markdown` source types may still exist in internal contracts but are not supported in the current user flow.

### Tab 1: Start from Idea

The AI automatically generates a script from your idea.

| Field | Required | Description |
|-------|----------|-------------|
| **Title** | ✅ | Project title |
| **Idea Brief** | ✅ | Video idea description (free-form) |
| **Target Duration** | - | Presets: 15/30/45/60/90 seconds; Custom accepts any finite value greater than zero. Approximately 3 minutes is guidance, not a hard maximum. |
| **Content Goal** | - | Content goal (e.g. educational, entertainment) |

→ Clicking "Create Project": creates the project → AI generates a script → redirects to the project page

### Tab 2: Start from JSON

Paste a JSON script (e.g. generated by ChatGPT).

| Field | Required | Description |
|-------|----------|-------------|
| **Title** | - | Project title (defaults to "Untitled" if empty) |
| **JSON Script** | ✅ | Scene script in JSON format (paste directly or upload a file) |

→ You can also upload `.json` or `.txt` files.

#### JSON Script Format

```json
{
  "scenes": [
    {
      "type": "hook",
      "text": "Can you believe AI can create a video in just 60 seconds?",
      "image_prompt": "A futuristic holographic AI interface creating video content...",
      "speaker": "host",
      "mood": "exciting",
      "composition": "medium shot, centered",
      "style_tags": ["cinematic", "sci-fi"]
    }
  ]
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `type` | ✅ | Scene type (hook, body, cta, etc.) |
| `text` | ✅ | Narration/script text |
| `image_prompt` | - | Image generation prompt (used first in the visual plan) |
| `speaker` | - | Speaker (e.g. host, narrator) |
| `mood` | - | Mood (e.g. exciting, calm) |
| `composition` | - | Composition (e.g. close-up, wide shot) |
| `style_tags` | - | List of style tags |
| `display_text` | - | On-screen display text (subtitle override) |
| `duration` | - | Scene duration in seconds |

### Common Settings

- **Model Defaults**: Select models for script/image generation per category
- **Style Preset**: Choose from `default`, `cinematic`, `dynamic`, `minimal`

### Duration, Output, and Encoding Contracts

These are separate contracts:

| Choice | Accepted values | What it means |
|---|---|---|
| Content format | `short` only | `long` exists in the enum but validation rejects it as not available yet. |
| Target duration | 15/30/45/60/90 presets or a finite Custom value `> 0` | Planning intent. Presets resolve to ±10% feasibility bands; neither the target nor its band guarantees achieved MP4 duration. There is no enforced 180-second maximum. |
| Output preset | `short_vertical`, `short_square`, `short_landscape` | Geometry only: 1080×1920, 1080×1080, or 1920×1080, each at 30 fps. |
| Encoding profile | `preview`, `standard`, `high_quality` | H.264/AAC defaults with CRF/preset pairs 28/`veryfast`, 23/`fast`, and 18/`slow`. |

New typed settings default to `short_vertical` and `standard`. A project with no
settings row resolves as `legacy_default`: vertical H.264/AAC, CRF 18/`fast`.
`legacy_default` is read-only compatibility state and cannot be submitted as an
encoding choice; it is not the same as `standard`.

Typed settings persistence is shipped, and the renderer itself has real-FFmpeg
coverage for square and landscape across the three encodings (the current
vertical path has separate render acceptance). However, the current
approval/worker path does not yet consume a project's typed settings. Until the
approval snapshot and worker propagation slices in
[`adr/008-typed-project-settings.md`](adr/008-typed-project-settings.md) land,
legacy generated and Timeline renders retain their existing vertical output.

Code/test evidence: `packages/creator-domain/creator_domain/models/duration_preset.py`,
`packages/creator-domain/creator_domain/models/project_settings.py`,
`packages/creator-domain/creator_domain/models/output_spec.py`,
`packages/creator-domain/tests/test_project_settings.py`,
`apps/studio-web/src/__tests__/IdeaFormDuration.test.tsx`, and
`packages/creator-service/tests/test_output_preset_ffmpeg.py`.

## Pipeline Stages

After project creation, generation tasks advance to explicit review gates; the
review gates do not advance automatically:

```
IDEA_READY → SCRIPT_GENERATING → SCRIPT_REVIEW
    → VISUAL_PLAN_GENERATING → VISUAL_PLAN_REVIEW
    → VISUAL_ASSET_GENERATING → VISUAL_ASSET_REVIEW
    → AUDIO_GENERATING → SUBTITLE_GENERATING
    → RENDER_GENERATING → FINAL_REVIEW
```

| Stage | Description | Model Used |
|-------|-------------|------------|
| **SCRIPT_GENERATING** | Generate script from idea (skipped for JSON input) | Ollama (qwen3:4b) |
| **SCRIPT_REVIEW** | Review and approve the generated script | - |
| **VISUAL_PLAN_GENERATING** | Generate visual plan (prompts) per section | Ollama (qwen3:4b) |
| **VISUAL_PLAN_REVIEW** | Review and approve the visual plan | - |
| **VISUAL_ASSET_GENERATING** | Generate images | Stable Diffusion (local) |
| **VISUAL_ASSET_REVIEW** | Review and approve generated images | - |
| **AUDIO_GENERATING** | Convert script text to speech (TTS) | Qwen TTS (local) |
| **SUBTITLE_GENERATING** | Generate subtitles (SRT) from audio | Whisper small (local, configurable) |
| **RENDER_GENERATING** | Combine images + audio + subtitles into final video | FFmpeg |
| **FINAL_REVIEW** | Review the final video | - |

## Review and Approval

At each `_REVIEW` stage you can **Approve** or **Reject**.

### Project Page

The project page shows the current pipeline stage and review status.
- **Approve**: Automatically advances to the next stage
- **Reject**: Regenerates the current stage

There are two distinct render entries:

- **Generated script flow:** idea → generated script → script approval → visual
  plan approval → visual asset approval → audio/subtitles/render → final approval.
  `apps/api/tests/test_script_generation_flow.py::test_script_generation_vertical_slice`
  covers the API slice with fake services; provider calls are mocked there.
- **Authored Timeline flow:** save a Timeline, preview/compile its current revision,
  then explicitly approve that same revision with
  `POST /api/creator/runs/{run_id}/approve-timeline-render`. The worker reloads the
  saved revision and persisted `TIMELINE_REVIEW` approval before FFmpeg. A stale
  revision is rejected and must be previewed again. See
  `apps/api/tests/test_creator_timeline_render.py::test_explicit_approval_dispatches_persisted_revision`
  and `apps/worker-orchestrator/tests/test_timeline_worker_approval.py`.

The **Try the demo** path seeds synthetic PNG media and an authored Timeline at
`TIMELINE_REVIEW`; it calls no AI provider and grants no automatic approval.
`packages/creator-service/tests/test_demo_offline.py::test_real_seed_saves_renderable_png_and_pauses_for_review`
proves the offline seed. The full runtime acceptance in
`tests/integration/test_first_short_runtime.py::test_authenticated_demo_survives_restart_and_renders_downloadable_mp4`
uses real PostgreSQL, Redis, API, Celery, FFmpeg, and `ffprobe`, but still uses
synthetic media rather than paid providers.

Transient timeout/rate-limit failures are retried by selected Celery generation
and render tasks with bounded task-specific limits; retries do not bypass review
or revision checks. The final artifact is downloaded through the authenticated
`GET /api/creator/runs/{run_id}/artifacts/{artifact_id}/download` route. Local
files are returned as attachments; configured cloud storage returns an authorized
download redirect. Cross-workspace or mismatched run/artifact access returns 404
(`apps/api/tests/test_creator_artifact_download.py`).

### Review Page

When the pipeline reaches `FINAL_REVIEW`, an **"Open Review Page"** link appears.
The review page shows all generated assets at a glance:
- Full script
- Visual plan
- Generated images (per section)
- Audio playback
- Subtitles (SRT)
- Final rendered video playback

## External API Providers

You can use external APIs for higher-quality results instead of (or in addition to) local models.

### Estimated-spend admission controls

Before new provider work is dispatched, the service atomically reserves a conservative maximum
estimate for the task, including bounded fan-out and retry allowance. Set
`BILLABLE_PROVIDER_CALLS_ENABLED=false` to stop new billable calls while preserving usage reads and
artifact downloads. `GLOBAL_MONTHLY_ESTIMATED_BUDGET_USD` adds an operator-wide monthly ceiling;
workspace monthly cost quotas still apply independently. Operations without a configured bounded
cost model are rejected rather than admitted without a ceiling.

Failures known to occur before provider execution release their reservation. If provider execution
may have started but its outcome is unknown, the estimate remains conservatively committed so a
retry cannot silently exceed the approved maximum. These values are estimates for admission and
operational safety only: they are **not invoices, billing-accuracy guarantees, or substitutes for
provider-side spending limits and billing reports**.

### Supported Providers

|----------|----------|-------|---------------------|

| **LLM** | Anthropic | Claude Sonnet | `ANTHROPIC_API_KEY` |
| **LLM** | Google | Gemini 2.0 Flash | `GOOGLE_API_KEY` |
| **Image** | OpenAI | DALL-E 3 | `OPENAI_API_KEY` |

### Setting Up API Keys

The Settings page is currently a **read-only status page** — it does not support editing or saving API keys.
You can check whether each provider key is configured at `/settings`, but actual key values are managed via server environment variables.

This is a deliberate security decision: the API never writes `.env` from a request, never returns key values
(not even masked), never logs keys, and the browser never stores them. See
[Provider API Key Configuration](SECURITY.md#provider-api-key-configuration) in the Security Model for the full
supported deployment model, rotation procedure, and CSRF applicability.

#### Editing the .env File

Add your API keys to the `.env` file:

```bash
OPENAI_API_KEY=sk-your-openai-key
ANTHROPIC_API_KEY=sk-ant-your-anthropic-key
GOOGLE_API_KEY=your-google-api-key
STABILITY_API_KEY=sk-your-stability-key
ELEVENLABS_API_KEY=your-elevenlabs-key
```

> ⚠️ After setting or changing API keys, restart the API and worker: `docker compose restart api worker`

### Model Selection

When creating a project, select between local and remote models in the **Model Defaults** section.
- **Local**: Requires GPU services, free, slower
- **Remote**: Requires API keys, paid, faster and higher quality

If a ⚠️ icon appears next to a remote model, the corresponding provider API key is not configured.

#### Model Key vs Provider Model Name

The Studio uses **model keys** (logical identifiers) that map to provider-specific model names:

| Model Key (API/UI) | Provider | Actual Model Name |
|---|---|---|
| `qwen3-4b` | Ollama | `qwen3:4b` |
| `sd15` | Stable Diffusion | SD 1.5 |
| `whisper-small` | Whisper | `small` |
| `gpt-4o-mini` | OpenAI | `gpt-4o-mini` |
| `claude-sonnet` | Anthropic | `claude-sonnet-4-20250514` |
| `dalle-3` | OpenAI | `dall-e-3` |

Model keys use hyphens (not colons) and are always lowercase.

## Generated File Locations

With the default local storage adapter, generated assets use the configured
`ARTIFACT_ROOT` (normally `data/artifacts`) and run-scoped paths such as:

```
data/artifacts/<run_id>/
├── scenes/
│   ├── scene-hook-1.png        # Per-section images
│   ├── scene-body-1.png
│   └── ...
├── audio/
│   └── audio.wav               # TTS-generated audio
├── subtitles/
│   └── subtitles.srt           # Whisper-generated subtitles
└── render/
    └── output.mp4              # Current legacy path: 1080x1920, H.264, 30fps
```

### Artifact retention

By default, artifacts are automatically deleted **90 days** after creation.
Configure the window with the `ARTIFACT_RETENTION_DAYS` env var (values
<= 0 fall back to the default of 90 days):

- The `sweep_expired_artifacts` beat task (every 10 minutes) marks rows
  whose `expires_at` has passed by setting `delete_requested_at = NOW()`.
- The `retry_failed_artifact_deletions` task (every 5 minutes) then removes
  the file from storage and deletes the DB row, retrying transient failures
  with `FOR UPDATE SKIP LOCKED`.

To exempt a specific artifact from expiry, set `expires_at = NULL`
explicitly on its row (e.g. for a published/keep-forever artifact).

Requires Celery Beat to be running (see the `beat` service in
`docker-compose.yml`). Downloads return `410 Gone` once `expires_at` passes.

## Limitations

### GPU Memory

- GPU: NVIDIA GeForce GTX 1660 SUPER (6GB VRAM)
- GPU services (Stable Diffusion, TTS, STT) cannot run simultaneously
- A GPU lock is used — one GPU task must complete before the next can start

### Worker

- The development Docker Compose override (`docker-compose.dev.yml`) uses `watchfiles` which may restart the worker on file changes
- For stable execution, use a standalone worker:

```bash
docker compose run -d --name sfp-worker-direct --no-deps \
  -e REDIS_URL=redis://redis:6379/0 \
  -e DATABASE_URL=postgresql://short_form_user:short_form_password@postgres:5432/short_form_studio \
  -e OLLAMA_BASE_URL=http://ollama:11434 \
  -e STABLE_DIFFUSION_BASE_URL=http://stable-diffusion:7860 \
  -e TTS_QWEN3_BASE_URL=http://tts-qwen3:8100 \
  -e STT_WHISPER_BASE_URL=http://stt-whisper:8200 \
  -e ARTIFACT_ROOT=data/artifacts \
  -e GPU_LOCK_KEY=gpu:lock \
  -e GPU_LOCK_TIMEOUT_SECONDS=600 \
  -e PYTHONPATH=/app/src:/app \
  worker celery -A celery_app.celery_app worker --loglevel=info --pool=solo
```

### Networking

- Studio Web and API run on the same Docker network
- Studio Web is bound to localhost by default: `http://localhost:5174`
- The Vite proxy automatically forwards `/api` requests to the API server

### Rendering

- Video rendering uses FFmpeg and runs locally
- Current project render path: 1080x1920 (portrait), H.264, 30fps. The other
  typed output presets are validated and renderer-tested but are not yet
  propagated from project settings through approval to the worker.
- Subtitles are burned into the video
- Long-form rendering is not supported or acceptance-tested. Open work is tracked
  in [#884](https://github.com/yeongseon/short-form-studio/issues/884),
  [#885](https://github.com/yeongseon/short-form-studio/issues/885), and
  [#905](https://github.com/yeongseon/short-form-studio/issues/905).
